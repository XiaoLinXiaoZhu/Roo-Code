# CLI 代理层透明性设计

## 背景

在实现 CLI 代理层时，我们面临两个关键设计决策：

1. **是否应该告知模型命令被代理了？**
2. **输出格式应该如何设计？**

## 设计决策

### 1. 完全透明原则

**决策**：不向模型暴露命令拦截的存在。

**理由**：

- 代理层的目的是**优化输出格式**和**强制安全规则**，而非改变命令语义
- 模型不需要知道底层实现细节，就像用户不需要知道 grep 是用 ripgrep 实现的
- 暴露拦截机制会增加模型的认知负担，可能导致不必要的行为变化
- 保持接口简洁：模型只需关心"执行命令，获取结果"

**不实现的功能**：

- ❌ `--raw` 参数：不提供绕过代理获取原始输出的选项
- ❌ 拦截标记：不在输出中添加 `[INTERCEPTED]` 等标记
- ❌ 元信息：不返回"此命令已被优化处理"等提示

### 2. 输出格式一致性

**决策**：与现有 `search_files` 工具保持一致的输出格式。

**格式规范**：

```
path/to/file.ts
  1 | first line content
  2 | second line content
 10 | tenth line content

another/file.ts
 15 | some content here

Found 3 results.
```

**关键细节**：

- 行号使用 `padStart(3)` 右对齐（如 `  1`、` 10`、`100`）
- 行号与内容之间使用 `|` 分隔
- 文件路径使用相对路径
- 文件之间用空行分隔
- 结尾统计使用 `Found N results.` 格式

**理由**：

- 模型已经熟悉 `search_files` 的输出格式
- 一致的格式减少模型的解析负担
- 便于模型在不同工具间切换时保持一致的处理逻辑

### 3. 保守拦截策略

**决策**：遇到不支持的选项时，回退到原生命令执行。

**支持的命令和选项**：

| 命令 | 支持的选项                                                               | 不支持（回退原生）           |
| ---- | ------------------------------------------------------------------------ | ---------------------------- |
| grep | `-i`, `-r`, `-n`, `-C`, `-A`, `-B`, `-w`, `-F`, `--include`, `--exclude` | `-P`, `-o`, `-c`, `-l`       |
| cat  | `-n`                                                                     | `-v`, `-e`, `-t`, `-A`       |
| head | `-n`, `-c`                                                               | -                            |
| tail | `-n`, `-c`                                                               | `-f`, `--follow`             |
| find | `-name`, `-iname`, `-type`, `-maxdepth`                                  | `-exec`, `-delete`, `-mtime` |
| ls   | `-l`, `-a`, `-A`, `-R`, `-h`                                             | `--color`, `-S`, `-t`, `-X`  |
| wc   | `-l`, `-w`, `-c`                                                         | -                            |

**理由**：

- 确保功能正确性优先于优化
- 避免因不完整实现导致的行为差异
- 用户始终可以获得正确的结果

## 实现细节

### 拦截流程

```
用户命令 → ShellParser 解析 → 检查是否可拦截
                                    ↓
                            ┌───────┴───────┐
                            ↓               ↓
                        可拦截          不可拦截
                            ↓               ↓
                    CommandHandler      原生执行
                        执行              (execa)
                            ↓               ↓
                    格式化输出          原始输出
                            ↓               ↓
                            └───────┬───────┘
                                    ↓
                              返回给模型
```

### 安全强制

所有拦截的命令都会强制执行 `.rooignore` 规则：

- 被忽略的文件不会出现在搜索结果中
- 尝试读取被忽略的文件会返回错误
- 目录列表会过滤掉被忽略的条目
