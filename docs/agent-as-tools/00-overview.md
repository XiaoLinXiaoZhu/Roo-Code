# 架构概述与核心理念

## 1. 设计哲学

### 1.1 从"团队协作"到"工具使用"的范式转换

传统的 Multi-Agent 架构模拟人类团队协作：

- 经理分配任务给员工
- 员工完成后汇报结果
- 经理需要理解如何分配、如何协调

**新架构的核心洞察**：对于 AI 模型而言，"使用工具"比"管理团队"更自然。

```
传统思维：我需要委派一个子任务给代码专家去完成
新思维：我需要调用代码编辑工具来完成这个修改
```

### 1.2 核心设计原则

| 原则             | 描述                               | 实现方式                     |
| ---------------- | ---------------------------------- | ---------------------------- |
| **封装复杂性**   | 隐藏子任务的创建、管理、状态转换   | 工具内部处理所有委派逻辑     |
| **自然语言接口** | 用自然语言描述意图，而非结构化参数 | `query: string` 作为主要输入 |
| **结果导向**     | 只关心返回值，不关心执行过程       | 统一的返回格式               |
| **单一活动点**   | 主模型始终是唯一的决策者           | 子任务同步执行并返回         |

### 1.3 灵感来源

这个架构的灵感来自多个方向：

- **ReAct 模式**：Reason + Act 的极致简化
- **MCP (Model Context Protocol)**：标准化的工具接口
- **Cursor Composer**：将复杂操作封装为简单工具
- **函数式编程**：将副作用封装在纯函数内部

## 2. 架构对比

### 2.1 旧架构的认知负担

```typescript
// 旧架构：模型需要理解和管理这些概念
interface OldArchitectureConcepts {
	// 1. 任务层级
	parentTaskId: string
	childTaskId: string
	rootTaskId: string

	// 2. 状态管理
	status: "active" | "delegated" | "completed"
	awaitingChildId: string
	completedByChildId: string

	// 3. 模式系统
	mode: "code" | "architect" | "ask" | "expert"
	switchMode(): void

	// 4. 任务调度
	new_task(): void
	attempt_completion(): void

	// 5. 上下文传递
	todos: TodoItem[]
	message: string
}
```

**问题**：模型花费大量 token 在理解这些概念和做出决策上。

### 2.2 新架构的简化视图

```typescript
// 新架构：模型只需要理解工具的用途
interface NewArchitectureTools {
	// 搜索项目信息
	searchProject(query: string, options?: SearchOptions): SearchResult

	// 应用代码编辑
	applyEdit(files: string[], instruction: string): EditResult

	// 咨询专家意见
	consultExpert(domain: string, question: string): ExpertOpinion
}
```

**优势**：模型只需选择合适的工具并描述需求。

## 3. 核心概念定义

### 3.1 主智能体 (Main Agent)

- **角色**：唯一的决策者和用户界面
- **职责**：理解用户意图、选择工具、整合结果
- **特点**：保持人格和记忆的连贯性

### 3.2 工具化智能体 (Tool Agent)

- **角色**：封装在工具内部的专业智能体
- **职责**：执行特定领域的任务
- **特点**：对主模型透明，只暴露接口

### 3.3 自然语言接口 (NL Interface)

- **定义**：使用自然语言作为工具参数
- **优势**：降低使用门槛，提高灵活性
- **示例**：`applyEdit("把错误处理改成 try-catch")` 而非复杂的 AST 参数

## 4. 数据流设计

### 4.1 同步调用模型

```
┌─────────────────────────────────────────────────────────────────┐
│                         Main Agent                               │
├─────────────────────────────────────────────────────────────────┤
│  1. 接收用户请求                                                  │
│  2. 分析需求，选择工具                                            │
│  3. 调用工具（同步等待）                                          │
│  4. 接收结果                                                     │
│  5. 整合结果，继续推理或返回用户                                   │
└───────────────────────────┬─────────────────────────────────────┘
                            │
            ┌───────────────┼───────────────┐
            ▼               ▼               ▼
     ┌──────────┐    ┌──────────┐    ┌──────────┐
     │searchProj│    │applyEdit │    │consultExp│
     │  ect     │    │          │    │   ert    │
     └────┬─────┘    └────┬─────┘    └────┬─────┘
          │               │               │
          ▼               ▼               ▼
     ┌──────────┐    ┌──────────┐    ┌──────────┐
     │ ask mode │    │code mode │    │expert mod│
     │ (hidden) │    │ (hidden) │    │e(hidden) │
     └──────────┘    └──────────┘    └──────────┘
```

### 4.2 内部实现映射

| 新工具          | 内部模式        | 实际执行             |
| --------------- | --------------- | -------------------- |
| `searchProject` | ask             | 只读操作、搜索、分析 |
| `applyEdit`     | code            | 完整的编辑能力       |
| `consultExpert` | expert (自定义) | 深度推理、方案设计   |

## 5. 与现有系统的关系

### 5.1 复用现有基础设施

新架构**不是**完全重写，而是在现有系统上的**包装层**：

```typescript
// 内部仍然使用现有的委派机制
class SearchProjectTool {
	async execute(params: SearchParams): Promise<SearchResult> {
		// 1. 创建子任务（使用现有的 delegateParentAndOpenChild）
		// 2. 等待完成（使用现有的 reopenParentFromDelegation）
		// 3. 解析并返回结果
		// 关键：这些细节对主模型完全隐藏
	}
}
```

### 5.2 保持向后兼容

- 现有的 `new_task` 工具可以保留给高级用户
- 通过配置切换新旧架构
- 渐进式迁移，不影响现有功能

## 6. 预期收益

### 6.1 量化指标

| 指标               | 旧架构    | 新架构 | 改善  |
| ------------------ | --------- | ------ | ----- |
| 任务调度相关 token | ~500-1000 | ~0     | -100% |
| 模式切换决策时间   | 显著      | 无     | 消除  |
| 学习曲线           | 陡峭      | 平缓   | 降低  |
| 错误恢复复杂度     | 高        | 低     | 简化  |

### 6.2 定性收益

- **更好的用户体验**：主模型更专注于任务本身
- **更高的可维护性**：工具可以独立优化和升级
- **更强的可扩展性**：添加新工具不影响主模型逻辑
