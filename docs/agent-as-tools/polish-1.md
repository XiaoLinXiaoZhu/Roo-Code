## 回顾

agent as tool 的核心观点是将agent拉到tool层面，且纯化为工具，放弃“代理”、“协作”的概念。

## 存在的问题

我们一共有4个这样的工具：

1. 咨询专家
2. 代码编辑
3. 工具构建
4. 项目内搜索

但是它们都基于同一个 system-prompt，这导致模型的注意力被分散、工作质量下降。尤其是我们现在实际上是用指令去覆盖系统提示词中的指导。

在new-task 分发的时候，我们希望工具也能够定义调用时传入的系统提示词，对模式的系统提示词进行覆盖，从而当其以subagent启动时，能够获得更好的token开销和表现。

## 修改

原来：拼接指令和todo，从而控制模型行为

希望：直接配置不同的专有系统提示词，只将具体问题作为指令传入，不再使用todo，而是使用更好的系统提示词和指令分层指导模型行为。

## 提示词设计

### 咨询专家

按照问题分类直接设计不同的提示词 + 通过插槽灵活赋予角色。整体使用情景驱动的 long-cot 指导的 deep-thinking 风格提示词

### 代码编辑

系统提示词仅仅提供代码编辑规范，不增加额外约束。（因为它不负责debug等事情）

### 工具构建

工具构建仅仅提供工具构建规范，不增加额外约束。

### 项目内搜索

指导如何通过工具和lsp快速分析，不增加额外约束。

## 期望效果

高于基线

baseline：

- 每个模式的模式的role和instruction会被合并进系统提示，这一部分约束
- 通过subagent工具调用时创建的todo instruction，这一部分指导
