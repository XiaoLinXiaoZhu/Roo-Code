# 管道语义与元信息分离

## 背景

在实现 CLI 代理层时，我们面临两个输出处理问题：

1. **管道污染**：截断提示混入 stdout，影响下游命令
2. **上下文爆炸**：大输出占用过多 token，影响模型性能

## 设计决策

### 1. 统一截断处理

**决策**：所有 CLI 输出超过 50KB 时自动截断，保留尾部 40KB。

**理由**：

- 50KB ≈ 12500 token，是合理的上下文占用
- 保留尾部而非头部，因为最新输出通常更重要（错误信息、最终结果）
- 完整输出保存到文件，支持按需查看

**截断提示格式**：

```
[Output truncated: 20KB omitted, showing last 40KB]
Full output saved to: .roo/cli-output/2026-02-02T12-00-00_grep_pattern.txt
💡 To investigate: grep -n "keyword" .roo/cli-output/... or sed -n '1,100p' ...
```

### 2. stdout 与 metadata 分离

**问题**：截断提示混入 stdout 会污染管道

```bash
cat large-file.ts | grep "function"
```

如果截断提示在 stdout 中，grep 会匹配到提示信息中的关键词。

**决策**：将元信息与数据流分离，管道只传递纯净的 stdout。

**架构**：

```
┌─────────────┐     stdout      ┌─────────────┐     stdout      ┌─────────────┐
│   cat       │ ───────────────→│   grep      │ ───────────────→│   head      │
│             │                 │             │                 │             │
│  metadata ──┼──┐              │  metadata ──┼──┐              │  metadata ──┼──┐
└─────────────┘  │              └─────────────┘  │              └─────────────┘  │
                 │                               │                               │
                 └───────────────────────────────┴───────────────────────────────┘
                                                 │
                                                 ▼
                                    ┌─────────────────────────────┐
                                    │  最终输出 = stdout +        │
                                    │  合并的 metadata            │
                                    └─────────────────────────────┘
```

## 实现细节

### CommandResult 结构

```typescript
interface CommandResult {
	stdout: string // 纯净的数据流，用于管道传递
	stderr: string // 错误信息
	exitCode: number // 退出码
	truncated?: boolean // 是否被截断
	truncationMessage?: string // 截断提示（不混入 stdout）
}
```

### CliOutputTruncator

统一的截断处理器，处理所有 CLI 输出：

```typescript
const result = await truncateCliOutput(output, cwd, command)

if (result.truncated) {
	// result.output: 截断后的输出（尾部 40KB）
	// result.fullOutputPath: 完整输出的文件路径
	// result.truncationMessage: 截断提示信息
}
```

### 输出文件管理

- **存储位置**：`.roo/cli-output/`
- **文件命名**：`{timestamp}_{command-slug}.txt`
- **自动清理**：保留最近 20 个文件，旧文件自动删除
- **文件内容**：包含命令、时间戳、完整输出

### 处理流程

1. **拦截路径**（CommandInterceptor）：

    - Handler 生成 stdout 和 metadata 分离的结果
    - PipelineExecutor 只传递 stdout，收集所有 metadata
    - 最终应用统一截断处理

2. **原生路径**（Terminal 执行）：

    - 获取终端输出
    - 应用统一截断处理
    - 返回截断后的结果

3. **最终输出**（ExecuteCommandTool）：
    - 合并 stdout 和所有 metadata
    - 截断提示在输出末尾，不影响数据流

## 测试验证

```bash
# 大文件截断测试
cat very-large-file.ts
# 输出：最后 40KB + 截断提示 + 完整输出文件路径

# 管道语义测试
cat large-file.ts | grep "function" | head -10
# 管道中间的截断不会影响 grep 匹配
# 截断提示只在最终输出时显示
```
